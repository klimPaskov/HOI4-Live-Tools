# Rust foundation provenance

This port derives typed process reads, the own-country tag-index chain, focus and
research object semantics, and the 365-day calendar from smerss/Clausewitz-MCP
commit `97c85437081904d5ad07bae1623ec58d1c0a5b9e`, specifically
`calling/{mem,process/linux,api,game}.py`. Copyright (c) 2026 smerss.
The original MIT license is retained in `LICENSE.clausewitz`.

Rust modules `memory.rs`, `game.rs`, `calendar.rs`, `technology.rs`, `research.rs`, `research_ui.rs`, `technology_nodes.rs`, `own_focus.rs` and `platform/linux.rs` carry
source comments identifying this derivation. Other modules are new project code.
Current Linux ELF layouts were recovered independently from the installed build;
upstream 1.19.2 offsets were not copied as current-build evidence.

The owned Linux preview exposes observations and optionally ordinary clock keys.
Engine command execution remains quarantined in
the disclosed private upstream validation adapter until its transaction and
recovery semantics have been ported and tested. No raw process-write, injection,
console or foreign-country interface is exposed by this Rust MCP.

The action journal and X11 keyboard fallback modules are new project code.
X11 transport uses the MIT/Apache-2.0 licensed x11rb dependency. Keyboard bindings
were checked against the installed game GUI definitions; no game files are
redistributed. The optional clock adapter uses typed desired states, exclusive leases and memory
readback; it never calls the failed engine posting path.

The persistent Linux launcher, bounded socket connection and stdio framing, mutable mapping
cache, boot/auxiliary-vector exec witness and generated-child fixtures are new
project code. They do not derive an engine command interface or make the failed
upstream posting experiment safe to replay.

The explicit bounded Xauthority parser, display-peer checks, input authority and
clock adapter are new project code. The parser implements the authentication
record format; it does not copy dependency source. Current-build playthrough ID
semantics were independently checked against the installed executable. That
persisted ID is a campaign discriminator, not a proved load-generation token.

The technology catalog ports the upstream public-definition API concept while
using the independently recovered canonical database array and primary ID. It
excludes the upstream speculative folder array and old ID offset. The GUI
coordinate diagnostic module is new project code with independently recovered
current-build type, root, dimension and ratio witnesses; it supplies no click
adapter or client-origin claim. Both use fresh read-only snapshots.

The own research reader ports completed-membership and slot API concepts with
independently verified primary vtables, own-country links, canonical ID joins,
completion thresholds and signed 64-bit active counters. It excludes upstream
guessed progress units and eligibility calls.

The own research UI diagnostic uses the same derived own canonical technology
joins. Its UI implementation is new project code. Its widget, selected-slot,
view, container and button ownership/type fields were recovered independently
from the exact installed ELF and ordinary GUI definitions. No game files are
redistributed. Bounded primary RTTI observations classify actual renderer
metadata; they do not establish field layouts or ordinary click eligibility.
Exact renderer field layouts are accepted only after independent constructor
and getter recovery for the current build. Technology Info windows require
own-tree/status/catalog membership and a positively named ordinary research
control from the exact container registry. Raw disabled/alias/visibility fields
do not establish eligibility or input authorization.

Current technology-node and own-focus catalog/detail diagnostics use the same
derived canonical own-country semantics. Their node vectors, focus database/tree
membership, UI ownership and named control layouts were independently recovered
from the installed Linux ELF. Global focus database pointers supply membership
only; duplicate/null global entries do not grant own-tree ownership. Null detail
selection supplies no start-control binding. Current-node membership and local
window state do not establish visibility, hit routing or eligibility. These are
bounded read-only models, with no engine callbacks or strategic input adapter.

`node_binding.rs` is new project code from independent current-build constructor,
listener registration/dispatch and callback-capture disassembly. It associates
an exact owned control's data with the own canonical technology without calling
the callback. Unknown control types receive no inferred layout. Corrected
record-byte-16 extraction and byte-32 decoy tests follow the actual recorded
node-reader failure and independent register tracking; upstream offsets do not
serve as evidence for these fields. Full snapshot witnesses cover the binding
before filtered/paged output. Structural associations are not input authority.

`node_reuse.rs` is new project code that reuses bounded shared type metadata and
two independently recovered own-tree callback proofs within one node request.
Object identity and ownership remain fresh reads; final snapshot witnesses
recheck every reused proof byte. No process state is cached across requests.
It supplies no atomicity, visibility, event acknowledgement or input authority.

`node_detail.rs` is new project code from independently recovered current-build
renderer/resource getters and ownership links. It exposes one own ID's raw
fields and existing typed Info state. `node_hierarchy.rs` follows independently
proved exact renderer layouts and reciprocal links, constructor-created own
Container positions and owned graphics roots. Unknown ancestor payloads are not
traversed; hierarchy provenance is separate from ancestor country semantics.
`target_node.rs` is new project code for a narrower one-ID validation model:
complete public-key resolution and current-record canonical ownership, with GUI
binding/rendering only for target items. Every observed byte remains witnessed;
full-node validation is unchanged. No game assets, pixel textures, projection
or input adapter are included.

Bounded vectored Linux reads and final witness batching are new project code.
They preserve ordered all-or-error reads, current mappings, ownership and exec
witnesses around each batch. Generated children test partial reads and changed
protection/exec without modifying a game or changing kernel policy.

Distinct Unix shutdown metadata and generated-child exit fixtures are new
project code. They report the sole reaper's actual kernel wait result and do not
change signal delivery, shutdown policy or diagnose the game rendering error.
